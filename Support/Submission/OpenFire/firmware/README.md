# OpenFIRE IR·엔코더·버튼 확장

현재 사용자 보드와 같은 OpenFIRE **6.1-ca30987**에 원시 IR 좌표·실제 감지 플래그와 KY-040 입력 통신을 추가한 커스텀 빌드입니다. 버전은 `6.1-ca30987-obir3`로 표시됩니다. 대상은 **Raspberry Pi Pico RP2040 / 2MB / rpipico**입니다. 원본 Square LED 정렬·원근 변환 알고리즘은 유지합니다. 위쪽 50mm 보정과 엔코더 미세 조정은 PC에서 적용합니다.

`OpenFIRE-rpipico-obir3.uf2`는 일반 실행 코드 영역을 담습니다. 기존 USB ID·버튼·보정·LittleFS 저장 형식과 64KB 파일시스템 배치를 유지합니다. GP22·GP26·GP27·GP28은 아래 엔코더 전용으로 예약합니다. 다른 모델이나 플래시 배치에는 사용하지 마세요. 기존 OpenFIREApp의 통신은 유지하며, 우리 도구가 `0A`를 보냈을 때만 추가 검출·엔코더 프레임을 출력합니다. 점검 종료 시 확장 출력도 꺼집니다.

`obir3`는 USB 마우스·키보드·게임패드 HID 보고서를 보내지 않습니다. 연결 직후나 게임 종료 후 바탕화면에 조준·클릭을 전달하지 않으며, USB를 다시 연결해도 같습니다. USB 장치 이름과 종류는 유지됩니다. OB 실행기의 **게임 시작**에서 시리얼 IR 브리지가 켜지고, 게임 종료 시 브리지가 꺼집니다. 별도 점검 도구는 시리얼 카메라 점검을 사용합니다. 기존 HID 전용 프로그램으로 입력을 받으려면 이전 펌웨어가 필요합니다.

재장전은 GP0(Button A)의 **눌림에서 한 번** 전달합니다. 탄창이 삽입되어 계속 눌려 있는 동안에는 추가 장전을 보내지 않으며, 실제 해제를 받은 뒤 다음 눌림을 허용합니다. 조준 유실·복구도 이 잠금을 풀지 않습니다. 통신이 끊긴 동안 발생한 눌림은 복구 후 예약 실행하지 않습니다.

## KY-040 연결과 조작

USB를 뺀 상태에서 모듈의 핀 이름을 기준으로 연결합니다. 이번 사용자 모듈의 저항은 R1 Open, R2·R3 10k입니다.

| KY-040 | Pico GPIO | 물리 핀 |
|---|---|---|
| + | GP28, 펌웨어가 3.3V HIGH 출력 | 34 |
| GND | GND | 33 |
| CLK | GP26 | 31 |
| DT | GP27 | 32 |
| SW | GP22 | 29 |

GP28은 이 수동 엔코더의 풀업 두 개만 공급합니다. 카메라는 기존 3V3 OUT을 사용합니다. 다른 부하나 외부 전원을 GP28에 연결하지 않습니다. 두 10k 풀업이 모두 접지될 때 계산 전류는 약 0.66mA입니다.

시계 방향의 유효 회전 카운트마다 위로 2mm, 반대 방향은 아래로 2mm 조정합니다. 누르면 미세 조정만 0으로 돌아가며 기본 위쪽 50mm는 남습니다. 접점 바운스를 걸러낸 완전한 신호 주기 기준입니다. PC의 `Saved/ControllerInput/OpenFire/aim-adjustment.json`에 화면별로 저장하며 매 회전마다 보드 플래시를 쓰지 않습니다. 엔코더 실시간 입력은 IR 카메라 점검과 전용 IR 크로스헤어 테스트에서 사용합니다.

적용 전 `device_state.py`로 현재 설정을 읽고, BOOTSEL에서 picotool `save -a`로 전체 플래시를 백업합니다. 백업 파일과 설정 기록이 준비된 뒤 UF2를 쓰고 `verify`로 확인합니다. 적용 후 핀·보정·USB·버튼 설정을 이전 기록과 비교합니다. 문제가 생기면 같은 Pico의 전체 플래시 백업으로 복원할 수 있습니다. `flash_nuke`나 전체 초기화는 사용하지 않습니다.

이 PC에서는 BOOTSEL 백업 인터페이스의 Windows 드라이버가 없어 `Support/Archive/OpenFire/ram_backup`의 SRAM 전용 도구를 사용했습니다. 공식 Pico SDK 2.1.1의 `no_flash` 방식으로 빌드했고, UF2의 모든 적재 주소가 `0x20000000`부터 SRAM 안에 있는지 검사한 뒤 실행했습니다. 플래시 쓰기·삭제 함수를 포함하지 않으며 드라이버나 인증서를 설치하지 않습니다. 2MB를 각각 두 번 읽어 CRC32와 전체 데이터 일치를 확인하고, 적용 후에도 같은 방식으로 예상 코드와 기존 파일시스템의 바이트 일치를 확인했습니다. 백업 도구는 USB 전원을 끄면 사라지고 원래 플래시 실행으로 복귀합니다.

실제 보드의 원본 백업은 프로젝트 `Build/Testing/Verification/OpenFire/OpenFIRE-original-full.bin`과 `.uf2`, 설정 백업은 `prefs-before-obir.json`입니다. `flash-verification-obir.json`에 적용 후 전체 읽기 비교 결과가 있습니다. 원본 백업은 같은 보드의 복원용이며 일반 배포 펌웨어로 사용하지 않습니다.

이 파일을 빌드했다고 실물 보드에 적용한 것은 아닙니다. 실제 적용 여부는 해당 실행의 검증 기록으로 구분합니다.

## 빌드

프로젝트 루트에서 `Support/Submission/OpenFire/firmware/build.ps1`을 실행합니다. 필요하면 `-ArduinoCLI`와 `-Python`을 지정합니다. 공식 6.1 커밋과 고정된 하위 모듈을 사용하며, 원본 워크플로와 같은 OpenFIRE RP2040 코어 `4.5.4-tusb`로 빌드합니다. 이 스크립트는 보드에 쓰지 않습니다.

수정 내용은 `patch_firmware.py`, `OBIRTelemetry.h`, `OBIREncoder.h`, `OBIRQuadrature.h`에 있습니다. 배포 폴더의 `OpenFIRE-obir3-source.zip`에는 수정된 전체 펌웨어·라이브러리 소스와 원본 라이선스, 이 빌드 스크립트가 포함됩니다. 코어 소스와 툴체인은 [OpenFIRE Arduino-Pico](https://github.com/TeamOpenFIRE/arduino-pico/releases/tag/4.5.4-tusb) 배포를 사용합니다. 원본 저작권과 LGPL-2.1 라이선스를 유지합니다.

## 통신

`obir2`는 기존 `98` 원시 좌표와 `96` 조준 프레임 쌍 뒤에 `99 OBYE 01 08` 엔코더 프레임을 추가합니다. 총 17바이트이며 little-endian `uint32 position`, `uint32 presses`, CRC16-CCITT-FALSE 순서입니다. CRC는 `OBYE`부터 페이로드 끝까지 계산합니다. 누적 카운터를 사용하므로 일부 패킷을 놓쳐도 차이를 복구하고 재연결 시 첫 패킷은 기준값으로만 사용합니다.

원본 `ExecRunModeProcessing`은 버튼을 Poll하지만 눌림·해제를 시리얼로 보내지 않습니다. `obir2`에서는 명시적으로 `0A`를 받은 세션에 한해 이 루프에서도 기존 `90 index` 눌림·`91 index` 해제 패킷을 보냅니다. Trigger는 기존 GP15, 논리 인덱스 0을 유지합니다. PC 브리지는 최신 네 점 조준이 유효할 때만 사격을 전달하고, 추적 유실 중 눌러 둔 버튼을 복귀 후 자동 발사하지 않습니다.

점검 중 커스텀 빌드에만 단일 바이트 `0A`를 보내면 원본 `96` 좌표 프레임과 함께 `98 OBIR 01 16` 확장 프레임을 보냅니다. 총 31바이트이며 little-endian `uint32 sequence`, `uint8 seen`, `uint8 diamond`, `uint16 x0,y0,...,x3,y3`, CRC16-CCITT-FALSE 순서입니다. CRC는 `OBIR`부터 페이로드 끝까지 계산합니다. 감지 비트가 꺼진 슬롯의 좌표는 0이며 검출점으로 사용하지 않습니다. 센서 슬롯 번호는 실제 LED 번호가 아닙니다.

보드의 오류 또는 통신 중단은 LED 0개와 구분합니다. 원시 검출은 일반 카메라 영상이나 LED의 고유 ID를 제공하지 않습니다. 현재 PC 도구는 상단 2개·하단 2개인 Square 설치를 기준으로 합니다. 개별 위치 번호 확인은 상단 왼쪽·상단 오른쪽·하단 왼쪽·하단 오른쪽 순으로 가리는 선택 기능입니다. 검출 보기와 설치 가이드에는 등록이 필요하지 않습니다.

`set_square.py --port COM6 --backup-prefix <프로젝트 내 백업 경로>`는 현재 설정을 백업한 뒤 `IrLayout` 값만 Square로 저장하고 전체 설정을 다시 비교하는 개발용 설정 도구입니다. 확인한 `6.1-ca30987-obir1 / rpipico`에만 사용하며, 펌웨어·핀·USB ID·보정 수치를 변경하지 않습니다.
