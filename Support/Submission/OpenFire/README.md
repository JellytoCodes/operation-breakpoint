# Operation Breakpoint IR Controller

OpenFIRE 건컨트롤러의 조준 좌표와 버튼을 읽어 OperationBreakpoint에 전달하는 Windows 전용 도구입니다. 게임의 조준·발사·재장전·훈련 보정 완료 신호를 연결합니다.

## 실행

본 게임 패키지는 프로젝트의 **`Build/Submission/Windows/OB.exe`**로 실행합니다. 아래 `OBIRController.exe`는 별도 점검 도구입니다.

현재 `obir3` 펌웨어는 바탕화면 조작을 막기 위해 USB 마우스·키보드·게임패드 입력을 보내지 않습니다. 보드를 연결해 둔 상태로 작업할 수 있으며, OB 실행기에서 **게임 시작**을 누르면 시리얼 IR 브리지가 동작합니다. 게임 종료 시 입력도 종료됩니다. 카메라 확인은 점검 도구의 **IR 카메라 점검**을 사용합니다. 아래 HID 장치 선택·조준 보정·연동 시작 절차는 이전 HID 펌웨어용입니다.

1. `Support/Dist/Submission/OpenFire/OBIRController.exe`를 실행합니다.
2. 보드를 연결하고 장치 목록에서 사용할 OpenFIRE 장치를 선택합니다. 마우스 모드로 동작하는 보드가 필요합니다. 기본 탐색 대상은 공식 USB VID `F143`입니다.
3. 건컨트롤러를 움직여 조준 표시와 버튼 상태를 확인합니다. 버튼 기본값은 왼쪽=방아쇠, 오른쪽=재장전, 가운데=훈련 보정 완료입니다. 실제 배선·펌웨어의 마우스 버튼 매핑에 맞춰 바꿀 수 있습니다.
4. 현재 IR 테스트는 OpenFIRE 원본 Square 계산에 아래의 **위쪽 50mm + KY-040 미세 조정**을 사용합니다. 별도 표적 등록은 필요하지 않습니다. 일반 HID용 **조준 보정**은 선택 기능이며, 전용 IR 테스트에는 그 PC 보정 행렬을 적용하지 않습니다.
5. **언리얼 연동 시작**을 누르고 게임을 `-OBOpenFire` 옵션으로 실행합니다. 에디터에서는 `run_game.ps1 -Map Training` 또는 `run_game.ps1 -Map Stage01`을 사용할 수 있습니다. 보정한 디스플레이에서 게임을 전체 화면으로 실행하세요.

사격 스위치는 GP15, 재장전 스위치는 GP0(Button A / 우클릭에 대응하는 논리 버튼)를 사용합니다. 재장전 스위치는 GP0(물리 1번)과 GND에 연결합니다. IR 브리지는 재장전 버튼을 처음 누를 때 한 번만 전달하고, 탄창이 삽입되어 계속 눌린 동안에는 추가 장전하지 않습니다. 탄창 제거로 버튼이 해제되어야 다음 눌림을 받을 수 있습니다. 조준 유실 뒤 복구해도 장전 잠금은 유지합니다. 가운데 버튼의 **보정 완료**는 훈련 단계에 보내는 완료 신호이며 화면 보정을 자동으로 수행하는 버튼은 아닙니다.

일반 게임 실행에서는 OpenFire 수신부가 생성되지 않습니다. 본패키지의 `OB.exe`가 IR 모드를 지정합니다. 실행기의 **COM 포트**에서 **사용 안 함**을 선택하면 기존 마우스·게임 입력으로 실행합니다.

### 상황별 버튼 동작

| 모드 | 방아쇠 | 장전 |
|---|---|---|
| Interaction | LED 검출 없이 타이틀 시작·스킵·안내 넘기기·결과 선택 | 차단 |
| Shooting | 유효한 화면 내 IR 조준에서 새로 당겼을 때만 발사 | LED 검출과 무관하게 1회 처리; 훈련 단계별 허용은 유지 |
| Travel | 스플라인 이동 중 발사 차단 | 아래 bool 옵션이 켜져 있을 때만 허용 |
| Disabled | 연출·QA 미리보기·입력 차단 상태에서 사용 안 함 | 차단 |

모드는 `AOBPlayerController::GetGunInputMode()`가 현재 UI·훈련·이동 상태에 따라 선택합니다. `OB > Input > Gun`의 **Allow Reload While Moving** (`bAllowReloadWhileMoving`)은 기본 `false`이며, 블루프린트 기본값이나 실행 중 bool 변경으로 이동 중 장전만 켤 수 있습니다. 장전 버튼을 계속 누른 상태에서 허용 모드로 바뀌어도 예약 장전하지 않으며, 실제 해제 후 새 눌림이 필요합니다.

브리지는 조준이 필요한 사격 신호와 조준이 필요 없는 UI 눌림·유지를 별도 카운터로 전달합니다. LED를 벗어난 채 방아쇠를 누르고 다시 조준해도 지연 발사하지 않습니다. USB 통신 유실·창 포커스 복귀·모드 전환 후에는 기존 누름을 이어서 실행하지 않습니다. 이 기능은 언리얼 게임 코드와 브리지 양쪽 변경이므로 게임과 `OB.exe`를 함께 재빌드해야 합니다.

## 본 게임 패키지

1. OpenFIREApp이나 별도 IR 점검에서 COM 포트를 사용 중이면 점검을 종료합니다.
2. `Build/Submission/Windows/OB.exe`를 실행합니다. 이름·병사 군번을 직접 입력하거나 비워 둡니다. 빈 항목은 **게임 시작**을 누를 때 시연용 임의 값으로 자동 입력됩니다.
3. **COM 포트**, **인식 카메라**, **DISPLAY**에서 사용할 장치를 선택하고 **게임 시작**을 누릅니다. 새로 연결한 장치는 **새로고침**으로 목록에 반영합니다. COM 포트의 **자동 검색 (AUTO)**는 OpenFIRE 보드를 찾고, 카메라를 직접 선택하면 장치 ID로 고정합니다. 기본 카메라 입력은 1280×720 MJPEG 30fps입니다.
4. 카메라 미리보기의 **PLAYER AREA** 안에서 선 자세 보정을 완료하면 **디스플레이 1**에 타이틀이 열립니다. 보정 진행률은 실행기에 표시하며, 미리보기는 항상 위에 고정하지 않습니다. 방아쇠로 시작하며, 같은 IR 입력을 훈련장과 Stage_01의 조준·사격에 사용합니다.

검증한 X 영점과 Y 기본·미세 조정은 패키지의 `Saved/ControllerInput/OpenFire/aim-adjustment.json`에 들어 있습니다. 디스플레이 1의 설정에 기존 영점을 복사했으며, 노브는 Y축을 2mm씩 조정하고 누르면 미세 Y만 초기화합니다. 원본 OpenFIRE 좌표를 사용하며 테스트용 70% 세로 감도 곡선은 적용하지 않습니다.

게임이 종료되면 실행기가 IR 점검 모드를 해제하고 COM 포트와 자세 인식 카메라를 정리합니다. `OB.json`에서 실행 디스플레이·USB 자동 검색·OSC 포트를 설정합니다. 실행 기록은 패키지의 `Saved/Launcher`에 남습니다. Python이나 ESP32 도구를 별도로 실행할 필요는 없습니다.

재빌드는 `Support/Testing/Packaging/build_ir_package.ps1`을 사용합니다. 게임 소스·타이틀·훈련장·Stage_01을 패키징하고 IR 실행기와 기존 MediaPipe를 묶습니다. 테스트 맵은 제출용 콘텐츠에서 계속 제외합니다.

별도 `OBIRController.exe`에서 만든 HID 화면 보정 행렬은 `%LOCALAPPDATA%/OperationBreakpoint/OpenFire/settings.json`에 장치 경로와 대상 화면별로 저장됩니다. USB 포트나 디스플레이 구성이 바뀌면 목록과 보정값을 다시 확인하세요. 점검 도구는 보드의 플래시·기존 보정값을 변경하지 않습니다.

## IR 카메라 점검

COM 포트를 선택하고 **IR 카메라 점검**을 누르면 장치를 Docked 모드로 전환하고, 버전·보드 응답 확인 후 선택한 디스플레이에 전체 화면 점검 창을 엽니다. **Esc** 또는 **점검 종료**로 빠져나옵니다. 점검하는 동안 게임 전송은 중지됩니다. 종료 시 Undock 명령을 보내 COM 포트를 해제합니다. `obir3`는 이때도 바탕화면 HID 입력을 보내지 않습니다. 강제 종료 후 보드가 응답하지 않으면 USB를 다시 연결하세요.

카메라 점검은 소스로 통신 형식을 확인한 **펌웨어 6.1 / 6.2**를 지원합니다. 사용자 보드의 `6.1-ca30987`도 포함합니다. 원본 보정 좌표 표시는 업데이트 없이 사용할 수 있습니다. **실제 LED 검출 확인은 `obir1` 이상, KY-040 수신은 `obir2` 이상 확장 펌웨어가 필요합니다. 현재 버전은 `6.1-ca30987-obir3`입니다.** 원본 OpenFIREApp과 동시에 같은 COM 포트를 열 수 없습니다. 점검 버튼은 설정 쓰기·핀 변경·펌웨어 업데이트·반동 테스트를 수행하지 않습니다.

### 가늠좌 높이와 KY-040 Y축 조정

가늠좌로 중앙을 겨눴을 때 모든 위치에서 같은 방향으로 빗나가는 X 영점은 `aim-adjustment.json`의 화면별 `x_shift`로 원본 X 좌표에 한 번 더합니다. 값은 화면 너비에 대한 정규화 이동량이며, 양수는 오른쪽·음수는 왼쪽입니다. 현재 시험값은 해당 설정 파일에서 확인합니다. 보드의 LED 정렬·원근 변환이나 X 감도는 바꾸지 않습니다. Y 미세 조정 및 노브 누름은 X 영점을 변경하지 않습니다. 점검·HID 전송·전용 IR 테스트가 같은 영점을 사용합니다.

원본 OpenFIRE의 네 점 정렬·원근 변환 결과에 화면 위쪽 **50mm**를 더합니다. X축은 바꾸지 않습니다. Display2의 EDID 높이 390mm 기준으로 Y 정규화 좌표에서 `50/390`을 빼며, 2160px 화면에서는 약 277px입니다. 카메라가 LED를 실제로 검출하는 시야를 넓히는 기능은 아닙니다.

KY-040의 Y 미세 조정 범위는 **-500~+500mm**, 한 칸은 기존 **2mm**입니다. 기존 ±100mm 제한에서 더 내리거나 올릴 수 있으며 저장된 값도 다음 실행에 복원됩니다. 음수는 아래쪽, 양수는 위쪽 조정입니다. 노브를 누르면 미세 조정만 0으로 돌아가고 X 영점은 유지합니다. 이 범위는 소스 실행 테스트·별도 점검 도구·본패키지의 `OB.exe`에 적용됩니다. 디스플레이 1에서 확인한 X축 추가 5px와 Y 영점은 본패키지의 `Saved/ControllerInput/OpenFire/aim-adjustment.json`에 반영되어 있습니다.

KY-040을 돌리면 유효 회전 카운트마다 **2mm**씩 미세 조정합니다. 시계 방향은 위, 반대는 아래이며, 노브를 누르면 미세 조정만 0이 되고 기본 50mm는 유지됩니다. 화면에 적용 중인 기본·미세·합계 값을 표시합니다. 값은 `Saved/ControllerInput/OpenFire/aim-adjustment.json`에 화면별로 저장합니다. 점검 화면과 IR 테스트가 같은 값을 사용합니다. 일반 HID 모드에서는 저장된 값을 적용하며, 실시간 노브 수신은 IR 점검 또는 전용 IR 테스트를 실행한 동안 동작합니다.

USB를 뺀 상태에서 KY-040 `+→GP28(34번)`, `GND→GND(33번)`, `CLK→GP26(31번)`, `DT→GP27(32번)`, `SW→GP22(29번)`으로 연결합니다. GP28은 확인된 10k 풀업 두 개만 공급하고 카메라는 기존 3V3 OUT에 둡니다. 자세한 조건은 `firmware/README.md`를 따릅니다.

### LED 검출과 고정 번호

현재 도구는 **상단 2개·하단 2개(Square)** 설치를 기준으로 사용합니다. 확장 펌웨어에서는 센서가 실제 감지한 점만 **실제 검출 0~4 / 4**로 집계합니다. 센서의 1024×768 좌표 평면에 검출점을 표시하며, 화면 오른쪽 설치도는 **1 상단 왼쪽 / 2 상단 오른쪽 / 3 하단 왼쪽 / 4 하단 오른쪽**으로 고정합니다. 설치도 위치와 카메라 센서상의 점 위치는 구분됩니다.

**LED 설치 가이드 (G)**를 누르면 선택한 디스플레이 전체에 실제 설치 위치를 표시합니다. OpenFIRE 원본 앱과 같이 와이드 화면은 가로 **30%·70%**, 4:3 화면은 **20%·80%** 지점의 위아래 테두리에 표식을 표시합니다. LED 중심을 표식의 가로 위치에 맞춰 화면 테두리 바깥에 부착합니다. 위아래의 왼쪽 LED끼리, 오른쪽 LED끼리 같은 세로선에 맞춥니다. **Esc 또는 가이드 화면 클릭**으로 닫습니다. 카메라 점검 중 열었다면 닫을 때 점검 화면으로 돌아갑니다. USB 연결이나 위치 번호 등록 없이도 가이드를 사용할 수 있습니다.

배치와 보드의 Square 설정이 맞아야 조준 계산이 맞습니다. 실제 연결 보드에는 Square를 저장했으며 기존 핀·USB·보정 수치는 유지했습니다. LED 설치 위치를 확정한 뒤 조준 보정을 다시 확인하세요. 가이드 표시 자체는 보정값을 저장하거나 게임 입력을 보내지 않습니다.

검출 개수와 점 위치만 볼 때는 별도 등록이 필요하지 않습니다. 개별 LED와 설치 위치 번호까지 연결해 확인하려는 경우에만 아래의 **위치 번호 확인(선택·R)**을 사용합니다.

1. 카메라를 움직이지 않게 고정하고 LED 네 점이 모두 검출되도록 합니다.
2. **위치 번호 확인(선택·R)**을 누릅니다.
3. 안내에 따라 **상단 왼쪽 → 상단 오른쪽 → 하단 왼쪽 → 하단 오른쪽** LED를 한 개씩 잠깐 가립니다. 각 단계에서 가린 LED를 다시 보이게 한 뒤 다음 위치를 가립니다. 실제 건컨트롤러 버튼은 필요하지 않습니다.
4. 등록 후 초록은 해당 LED 검출, 회색 점선은 미검출 LED의 이전 위치입니다. 노랑 검출점은 물리 위치가 아직 등록되지 않은 점입니다. 센서 슬롯이 바뀌어도 설치 위치 번호는 바꾸지 않습니다.

전체 유실·큰 이동·대응 모호함·통신 중단 뒤에는 번호를 추정해 붙이지 않고 기준점을 해제합니다. 다시 네 점을 보이게 하고 R로 등록합니다. 대칭 배치의 동일한 IR LED는 고유 ID를 보내지 않으므로, 연결을 새로 시작할 때도 실제 위치 등록이 필요합니다. 실제 LED의 가림과 물리 번호 대응은 실물에서 확인해야 합니다.

**Tab / 검출·원본 보기**로 기존 OpenFIREApp 방식의 조준점·배열 중심 표시도 볼 수 있습니다. 그 화면의 보정점 A~D는 물리 LED 번호가 아닙니다. **IR 화면 미리보기**는 실물 없이 표시를 확인하는 모의 화면이며 실물 검출로 집계하거나 게임에 전송하지 않습니다.

### 카메라가 가리키는 위치와 거리 영향

검출 화면 오른쪽의 작은 화면에 **청록색 십자**로 보드가 계산한 조준점을 표시합니다. 별도 LED 번호 등록 없이 사용할 수 있습니다. 왼쪽 원시 검출도는 1024×768 센서 평면이고, 오른쪽 조준점은 원근 변환과 보드 보정이 적용된 화면 좌표입니다. 왼쪽의 **회색 십자는 고정된 센서 중심**이며 오른쪽의 움직이는 조준점과 구분합니다. 오른쪽 화면은 선택한 디스플레이의 종횡비를 따릅니다.

실제 네 점과 같은 샘플의 조준 좌표를 함께 받았을 때만 청록색 십자를 표시합니다. 부분 검출·겹친 점·통신 중단에는 조준 미확인을 표시합니다. 화면 밖 좌표는 화면 안 조준점으로 붙이지 않고 **청록색 방향 화살표·화면 밖 문구·정규화 좌표(%)**를 표시합니다. 화살표는 화면 밖을 향한 방향 표시입니다. 이 조준점에는 보드에 저장된 보정값이 사용됩니다. 도구의 별도 PC 조준 보정과 게임 내 좌표를 모두 적용한 최종 사격 지점은 아니므로, 설치를 마친 뒤 실제 화면 표적과 맞는지 확인하세요.

전체 화면에서는 **센서 영역의 가로·세로 점유율, 최소 점 간격(px), 시야 끝 여유(px)**를 함께 보여줍니다. 점 간격이 작거나 가장자리에 가까우면 안내를 표시합니다. 이는 현재 센서상의 분리 정도와 시야 여유를 보는 참고 기준이며 실제 거리(m)나 검증된 사용 가능 거리를 뜻하지 않습니다.

거리가 멀어져 네 점이 모이는 현상은 정상입니다. 보드가 매 프레임 원근 변환을 계산하므로 이상적인 조건에서는 이 크기 변화를 보정합니다. 다만 점 간격이 좁아질수록 같은 센서 좌표 오차가 더 큰 화면 조준 오차로 확대됩니다. 너무 가까우면 LED가 시야 밖으로 나갈 수 있고, 너무 멀어지면 점 구분이나 검출이 불안정해질 수 있습니다. 실제 렌즈 왜곡과 총 조준선·카메라 사이의 위치 차이도 남을 수 있어, 네 점 검출만으로 거리별 정확도를 보장하지 않습니다.

확장 펌웨어의 빌드·백업·적용 방법은 `Firmware/사용법.md` 또는 소스의 `firmware/README.md`에 있습니다. 적용은 점검 실행과 별개입니다.

### 원본 조준 좌표 보기

표시는 사용자 원본 OpenFIREApp `3.0.3-d0f3334`와 같은 12개 좌표를 사용합니다.

- **초록 원 2개·청록 원 2개**: 펌웨어가 정렬·추정한 보정점 A~D입니다. 실제 설치 위치 번호로 사용하지 않습니다.
- **회색 사각형**: LED 점을 좌상 → 우상 → 우하 → 좌하 순으로 연결합니다.
- **회색 원**: 카메라의 조준 위치입니다. 총의 조준선과 비교합니다.
- **빨간 원**: IR 배열 중심입니다. 조준점과 구분됩니다.

점들은 카메라를 조준한 방향의 반대로 움직입니다. 이 화면은 영상이나 실제 카메라의 3차원 위치가 아니라, 보드가 계산한 LED 배치와 카메라 조준 관계를 2차원으로 보여 줍니다. 전체 화면은 원본 App처럼 1920×1080 기준 좌표를 대상 화면 크기로 변환합니다. 도구 안의 작은 미리보기는 같은 데이터를 16:9로 보여 줍니다.

수신을 기다리는 동안에는 점을 그리지 않으며, 0.75초 이상 새 프레임이 없으면 이전 점을 숨기고 수신 중단을 표시합니다. 이는 데이터 수신 상태이며 실제 IR 점 검출 상태는 아닙니다. **IR 화면 미리보기**는 실물 없이 표시를 확인하는 모의 화면으로, 게임 입력을 전송하지 않습니다.

점검 좌표에는 펌웨어가 추정한 점 위치가 포함됩니다. 표시된 점 4개를 실제 LED 4개 검출로 해석하지 않습니다. 공식 펌웨어의 이 점검 출력은 약 20Hz이며 게임 조준 입력으로 사용하지 않습니다.

## 언리얼 연결

### 전용 테스트 맵에서 IR 크로스헤어 확인

**`Support/Dist/Testing/IR_크로스헤어_테스트.cmd`** 또는 `run_ir_test.ps1 -Port AUTO -Display DISPLAY2 -CenterResponse 1.0`으로 테스트합니다. OpenFIREApp과 우리 도구의 IR 점검을 먼저 종료하세요. 스크립트는 `/Game/Tests/ControllerAim/Maps/L_ControllerAimTest`를 전체 화면으로 열고, 실제 IR 검출·보드 조준 좌표를 받아 초록 크로스헤어를 표시합니다. 회색 십자는 화면 중앙입니다. LED 네 점이 모두 검출되면 움직이며, 유실·겹친 배치·수신 지연·화면 밖 조준에는 초록 표시를 숨깁니다. 새 5점 등록 없이 보드 좌표에 위쪽 50mm와 엔코더 미세 조정을 적용합니다. Y 오프셋은 감도 곡선 뒤에 한 번 적용하여 감도를 낮춰도 물리 보정량이 줄지 않으며, 탄흔에도 같은 좌표를 사용합니다.

실행 화면은 **Display2**로 고정합니다. 현재 Windows 주 모니터인 `\\.\DISPLAY2`의 실제 픽셀 좌표와 해상도를 매 실행 시 읽어 `WinX/WinY`, `ResX/ResY`를 지정하고 저장된 창 위치는 사용하지 않습니다. 대상 정보는 실행 기록의 `display-target.json`에 저장합니다. 필요하면 `-Display DISPLAY1` 또는 `-Display PRIMARY`로 바꿀 수 있습니다.

이 테스트는 일반 HID 입력을 기다리지 않고 Docked 측정 좌표를 사용합니다. 점검용 수신은 약 20Hz이고, 브리지가 최신 상태를 로컬 OSC로 전달합니다. 조준 좌표 → 가상 총기 회전 → 실제 총구 Raycast 충돌점 → 크로스헤어 순서입니다. IR 카메라의 물리 3차원 위치나 총구 자세를 측정하는 기능은 아닙니다.

GP15의 Trigger 스위치를 한 번 누르면 현재 총구 충돌점에 원형 탄흔을 남깁니다. **Space**로도 현재 IR 조준점의 사격을 확인할 수 있습니다. 길게 눌러도 한 발만 처리하며, 추적 유실·화면 밖 조준 중에는 발사하지 않습니다. 탄흔은 최근 128개까지 유지합니다. 이 테스트에는 재장전·탄약 기능을 연결하지 않습니다.

`Support/Testing/ControllerAim/build_ir_shot_test.ps1`은 `Build/Testing/ControllerAimFire/Project`에 테스트용 소스 사본과 DLL을 빌드합니다. 해당 DLL이 있으면 실행 스크립트가 이 사본을 사용합니다. 편집 중인 원본 프로젝트 DLL을 덮어쓰거나 맵·UI 에셋을 저장하지 않습니다. `verify_ir_shots.py`는 별도 포트와 명시적인 모의 입력으로 화면을 띄우지 않고 사격·유실·복귀를 검사하며 실물 검증과 구분합니다.

상하 움직임이 크게 느껴지면 **F3으로 세로 중앙 반응을 5%p 줄이고, F4로 늘립니다. F5는 원본 100%**로 되돌립니다. 현재 값은 화면에 표시되며 10~200% 사이에서 조절합니다. 가로 좌표·화면 중앙·위아래 끝점은 유지합니다. 70%는 화면 중앙 부근의 세로 반응을 원본보다 낮추는 값이며, 가장자리에서는 이동이 빨라져 화면 끝까지 도달합니다. 전체 이동 범위를 줄이지 않는 비선형 보정입니다. 실제 LED 설치에 맞춘 광학 보정과는 구분되며, 유실·화면 밖 입력은 계속 숨깁니다.

배포 폴더의 `IR_크로스헤어_테스트.cmd`는 원본 좌표를 유지하는 **중앙 반응 100%**로 실행합니다. 70% 곡선은 중앙 외의 Y 좌표를 바꾸므로 가늠좌로 실제 화면 위치를 겨누는 기본 모드에는 사용하지 않습니다. 비교 실험에서만 `run_ir_test.ps1 -Port AUTO -CenterResponse 0.70`처럼 지정할 수 있습니다. 이전 `-VerticalScale` 이름도 새 중앙 반응 값의 별칭으로 받습니다. 실행 중 바꾼 값은 이번 테스트에만 적용하고 보드나 기존 IMU 설정에 저장하지 않습니다.

**Esc 또는 창 닫기**로 종료하면 IR 수신도 종료하고 Undock·COM 해제를 수행합니다. 강제 종료 후 포트가 잠겼다면 남은 테스트 프로세스를 종료한 뒤 다시 연결하세요. 기록은 `Saved/Tests/ControllerAim/IR/실행시각/`의 `bridge-status.json`, `ir-samples.csv`, `unreal.log`와 `Saved/Tests/ControllerAim/ir_*.csv`에 남습니다. 일반 게임 HID 연동과 기존 IMU 전용 테스트는 각각 기존 실행 방식을 유지합니다.

### 일반 게임 HID 연동

도구는 장치별 Windows Raw Input을 읽습니다. Windows 바탕화면 커서 위치나 다른 마우스의 상대 이동은 조준 데이터로 사용하지 않습니다. 좌표는 왼쪽 위 `(0,0)`, 오른쪽 아래 `(1,1)` 기준입니다. 보정 후 화면 밖으로 나온 좌표는 화면 모서리로 강제 보정하지 않으며 사격용 레이를 만들지 않습니다.

`127.0.0.1:9011`에 OSC 주소 `/ob/openfire/input`, 문자열 인자 1개(JSON)를 보냅니다. 사용자 지정 포트는 도구 `--port 9012`, 게임 `-OBOpenFirePort=9012`처럼 양쪽에 동일하게 지정합니다. 언리얼은 로컬 발신자만 허용합니다. 한 번에 게임/PIE 인스턴스 하나를 실행하세요.

수신부는 세션·순서·버튼 누름 누적값을 확인합니다. 중복·역순 패킷을 버리고, 짧은 클릭의 눌림 패킷이 유실되더라도 다음 패킷의 누적값으로 한 번 처리합니다. 한 패킷 사이에 여러 클릭이 모두 유실되면 가장 최근 누름 한 번으로 합칩니다. 오래된 여러 발을 한꺼번에 재생하지 않습니다. 0.35초 동안 전송이 끊기면 조준을 무효화하고 방아쇠를 놓습니다. USB 제거는 도구의 약 1초 주기 장치 확인 이후 전달됩니다.

게임 창이 활성화돼 있을 때 입력을 적용합니다. 연결·복귀 시 이미 누르고 있던 방아쇠로 발사하지 않습니다. 훈련의 길게 누르기·탄약·자세·이동·사격 허용 조건은 기존 컨트롤러 흐름을 사용합니다. 같은 장치의 기본 HID 클릭과 UDP 입력이 겹쳐 두 번 발사하지 않도록 OpenFire 모드에서 컨트롤러의 기본 왼쪽 클릭 발사를 차단합니다.

일반 HID에는 IR LED 유실 여부가 없습니다. 도구의 `connected`와 `aim_valid`는 연결 및 사용 가능한 좌표를 뜻하며 IR 추적 품질을 뜻하지 않습니다. 이번 확장의 검출 스트림은 Docked 점검용이며, 게임 실행 중 HID 유실 차단까지 연결한 것은 아닙니다.

## 검증과 개발

모의 입력은 도구의 **모의 입력** 또는 `--demo-stream 10`으로 보냅니다. 게임은 `-OBOpenFire -OBOpenFireDemo`로 실행해야 이를 받습니다. 모의 입력은 실물 검증과 구분됩니다.

소스 실행은 `python app.py`이며 Python의 tkinter와 `requirements.txt`가 필요합니다. `build.ps1`은 기존 Packaging Python 환경으로 테스트 후 독립 실행 파일을 만들고 실제 GUI의 초기화를 검사합니다.

자동 검사는 보정 계산·잘못된 보정 거부·Windows 좌표 범위·버튼 상태와 짧은 클릭·OSC 실제 소켓 송수신·시리얼 분할 프레임·종료 복귀를 확인합니다. 언리얼 검사는 `OperationBreakpoint.OpenFire`에 있습니다. 연결된 실물 보드에서의 추적·보정·사격 정확도와 전체 훈련 흐름은 별도로 확인해야 합니다.

공식 소스 조사 기준과 원본 앱 확인 내용은 [조사 기록](../../Archive/OpenFire/RESEARCH.md)에 있습니다.
